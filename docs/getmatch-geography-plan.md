# План: география поиска Getmatch

Дата: 02.11.2026. Статус: согласован 03.11.2026, реализован; приёмка — [отчёт](experiments/getmatch-geography-2026-11-03/report.md). Основание: [требования](source-geography-implementation-requirements.md).

## 1. Источник и доработка

Getmatch — агрегатор (не ATS), один публичный маршрут `GET https://getmatch.ru/api/offers` без авторизации.
Задача: переводить места брифа (`SearchPlace`) в значения геофильтра `l`, объявлять точность по каждому месту,
устранить GEO-001 (сравнение строк городов) и ложное объявление `locations=native`.

## 2. Проверенные возможности (живые запросы 02.11.2026 ~19:40 MSK)

| Что | Результат |
|---|---|
| Параметр | `l`, повторяемый; сервер принимает только `moscow`, `saints_p`, `regions_ru`, `relocate`, `remote` |
| Другие значения | `russia`, `kazan`, `kazan__tatarstan__russia`, `_cu-world`, параметры `location`, `city`, `location_id` — игнорируются (total = 954, вся лента) |
| Отрицательный контроль | `l=bogus` → 200 и вся лента; `l=moscow&l=bogus` → 537 (неизвестное значение молча отбрасывается) |
| Несколько значений | ИЛИ: `moscow`+`saints_p` = 553 (< 537+47, пересечение) |
| Пагинация | `offset`/`limit`, `l` сохраняется на следующих страницах (уже покрыто тестами) |

Смысл значений сверен по ID вакансий на полной выдаче каждого значения против полной ленты без фильтра
(поля `location_requirements[].format/ancestors`), расхождений 0:

| `l` | Фактический отбор | total |
|---|---|---|
| `moscow` | офис/гибрид в городе Москва (Мытищи, Люберцы — не сюда) | 537 |
| `saints_p` | офис/гибрид в Санкт-Петербурге | 47 |
| `regions_ru` | офис/гибрид в прочих городах РФ | 68 |
| `relocate` | офис/гибрид вне РФ **или** релокация за счёт компании (`relocation_company`) в другую страну; это не фильтр «помощь с релокацией» — см. [проверку 03.11](experiments/getmatch-salary-relocation-2026-11-03/report.md) | 48 |
| `remote` | любая удалёнка, география удалёнки не фильтруется | 398 |

`moscow ∪ saints_p ∪ regions_ru` = ровно «офис/гибрид в РФ». Вакансий вне всех значений нет.

## 3. Перевод места в `l` — согласованное исключение

Значений всего пять, они статичны во фронте Getmatch. **По решению пользователя от 02.11.2026** допускается
прямая таблица в `getmatch/geography.py` (исключение из §4 требований, отмечается комментарием в коде):

| Значение | Определение в коде |
|---|---|
| `moscow` | `geoname_id = 524901` (Moscow, RU) |
| `saints_p` | `geoname_id = 498817` (Saint Petersburg, RU) |
| `regions_ru` | `country = RU`, город не из строк выше |
| `relocate` | `country ≠ RU` |
| `remote` | удалёнка, без географии |

Сопоставление только по `geoname_id`/`country` из сохранённого брифа; строки названий не используются.

| Место брифа | `l` для офиса/гибрида | Статус |
|---|---|---|
| RU, вся страна | `moscow`, `saints_p`, `regions_ru` | `exact` |
| Москва / Петербург | `moscow` / `saints_p` | `exact` |
| Другой город РФ (вкл. Зеленоград 463829 — нет данных, что Getmatch относит его к `moscow`) | `regions_ru` | `broader` |
| Любое место вне РФ | `relocate` | `broader` |

`remote` добавляется к каждому месту (более гибкий формат подходит) со статусом `broader`;
при минимуме `remote_country`/`remote_worldwide` — только `remote`. Широкие результаты запрашиваются,
уточнение — задача постфильтрации. `second_chance` ослабляет только формат, геозоны мест не снимает.
`unsupported`/`not_found` для Getmatch не возникают: у любого допустимого места есть значение.

Каждое место брифа — отдельная ветвь (отдельный `SearchRequest` со своей пагинацией), как у HH.
Внутри ветви значения одного места объединяются нативным ИЛИ: например, `l=saints_p&l=remote`
или `l=moscow&l=saints_p&l=regions_ru&l=remote` для всей РФ. Повторы вакансий между ветвями
(общая `remote`) отсеивает движок по ID; страницы `remote` при этом скачиваются в каждой ветви.

## 4. Изменения кода

- `src/parsers/aggregators/getmatch/geography.py` — таблица значений и `resolve(place, minimum) → PlacePreparation`.
- `src/parsers/aggregators/getmatch/parser.py` — `prepare()` через `resolve()`, удалить сравнение строк;
  `locations=native` только если все места `exact`, иначе `local`.
- `src/parsers/interfaces.py` — `PlacePreparation` (исходное место, статус `exact|broader|unsupported|ambiguous|not_found|error`,
  отправленные значения, происхождение, причина) и `SearchPlan.places: tuple[PlacePreparation, ...] = ()`.
  Пустое значение по умолчанию — HH и ATS не затрагиваются.
- `src/engine/source_run.py` — `plan.places` в событие `search.plan` (без ветвлений по источнику).
- `tests/test_getmatch_geography.py`; `docs/geography-review.md` — статус GEO-001.

## 5. Тест-кейсы

| Случай | Ожидание |
|---|---|
| RU вся страна, офис | `moscow,saints_p,regions_ru,remote`; RU-часть `exact` |
| Москва 524901; Петербург 498817 | `moscow` / `saints_p` + `remote`, `exact` |
| Казань; Зеленоград 463829 | `regions_ru` + `remote`, `broader` |
| Кировск 548391 и Кировск 548392 | оба `regions_ru`, не `saints_p` |
| Ереван; вся Армения | `relocate` + `remote`, `broader` |
| 5 мест: вся RU + Ереван + Москва + … | 5 ветвей, у каждой свои `l`; статус по каждому месту; дубли вакансий отсеяны движком |
| Минимум `remote_country` / `remote_worldwide` | только `remote`, `broader` |
| `second_chance`, `published_after` | `l` сохраняется, `pa` добавляется |
| Пагинация ≥2 страниц (`moscow`+`remote` ≈ 700) | `l` во всех URL |
| Ошибка сети | ошибка источника, не пустая выдача |

## 6. Живая приёмка

Изолированный экземпляр (`JOB_SEARCH_DATABASE_PATH=/tmp/gm-accept/search.sqlite`), сценарий
`scripts/live_getmatch_geography.py`: `POST /api/v1/briefs` с `geoname_id` из подсказок → `POST /api/v1/runs`
→ события `search.plan` (с `places`) и URL всех страниц. Случаи: Москва, Петербург, Казань, вся RU,
Ереван + Москва, `remote_worldwide`. Контроль: ID исходных ответов против свежей ленты без фильтра
по правилам §2 (полнота и отсутствие лишнего). Доказательства: `docs/experiments/getmatch-geography-<дата>/`.
Плюс `ruff`, `mypy`, `pytest`.

## 7. Риски

- Сервер молча игнорирует неизвестное значение `l`: при переименовании геозоны запрос станет всей лентой.
  Таблица этого не обнаружит; см. открытый вопрос.
- Принадлежность городов Московской агломерации к `moscow` определяет Getmatch; по данным — только сам город.

## 8. Защита от сброса фильтра

Выбрана **проверка формы** (решение пользователя от 03.11.2026). Рассмотренные варианты:

Защита от молчаливого сброса фильтра (неизвестное `l` сервер игнорирует):

- **Сравнение totals.** Запрос без `l` с `limit=1` (нужен только `meta.total` всей ленты) против `meta.total`
  первой страницы ветви; не меньше — ошибка. Слабое место: ветвь «вся РФ + remote» покрывает 920 из 956,
  запас ~4 %, возможна ложная ошибка.
- **Проверка формы.** Страница `/vacancies` (~330 КБ) содержит `vacancies_list_filters_location_nested_N_<value>`
  для `moscow`, `saints_p`, `regions_ru`, `relocate`; отсутствие значения — ошибка подготовки.
  Ловит переименование, ложных срабатываний нет; `remote` в форме без значения, не проверяется.
