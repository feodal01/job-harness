## Условия

- Режим `offline`: имитация HH и Getmatch из настоящих страниц фикстур, задержки ответа взяты из прошлых живых замеров
  (HH: лента 0,98 с, карточка 0,76 с, профиль 0,93 с; Getmatch: лента 0,76 с, карточка 0,51 с).
- Лимиты из `settings.toml`: HH — 2 одновременных запроса, интервал 1,5 с; Getmatch — 1 запрос, интервал 1 с.
- Таймаут запуска поднят до 1800 с, чтобы сценарии не обрезались (в продукте 180 с).
- Два повтора; разброс между ними меньше 0,1 с, поэтому в таблице одно значение.
- Допущения имитации, которые нужно сверить живым замером: 30% вакансий общие для разных фраз; 40 работодателей на HH;
  на HH 5 страниц по 50 вакансий на каждую фразу.

## Выводы

1. **Время запуска = число запросов × интервал источника.** Доля времени, которую требует один только интервал,
   равна 1,00 во всех сценариях (`pacing_utilization`): HH 64 запроса × 1,5 с = 96 с, Getmatch 112 × 1 с = 112 с.
   Второй одновременный слот HH не помогает: ответ (≤1 с) короче интервала, слоты заняты на 28%.
   Сокращать время можно только **уменьшением числа запросов**; накладные расходы движка роли не играют.
2. **Профили работодателей — около половины запросов HH** (31 из 64). Каждый профиль удлиняет запуск на 1,5 с.
3. **Каждая показанная вакансия стоит отдельной карточки**: это главная статья расходов после профилей.
   Предфильтр по ленте сейчас почти ничего не отсекает: проверки профиля нет (П5), страна из ленты не извлекается.
4. **Фразы**: из трёх начата одна (П3). Время сценария с тремя фразами потрачено на первую.
5. **Источники параллельно**: два отдельных запуска уже идут параллельно; общее время равно более долгому (Getmatch).
6. **Getmatch**: 10 из 112 запросов — страницы ленты по 10 публикаций; при странице 100 их будет 1–10 на всю ленту.
   Вся лента (~921) при текущих настройках — около 940 запросов и 16 минут, в основном карточки.
7. **До первой карточки HH — 5–7 с**: 1–2 запроса к справочнику географии и лента перед первой карточкой, каждый через интервал 1,5 с.

Следствие для оптимизаций (спека 11.1): главный рычаг — меньше карточек и профилей на одну показанную вакансию
(точный предфильтр, профили только для прошедших жёсткие условия, кэш между запусками), а не параллельность внутри источника.

## Не измерено
