# Профроль: поиск и проверка роли вакансии

Статус: согласовано 07.11.2026. Общее правило вердиктов — в [README](README.md).

## Условие в брифе

Два обязательных поля:

- **Профроли** — одна или несколько ролей из справочника HH `professional_roles` (194 роли в 27 категориях,
  названия на русском и английском, английские — через `locale=EN`). Справочник хранится локально.
- **Поисковые фразы** — пишет пользователь или агент («python developer», «программист python»). Нужны
  источникам без ролей (ATS). Список синонимов из роли не генерируется.

Роли везде показываются названием, а не id («Программист, разработчик», а не «96»).

Старые брифы без ролей не переносятся и удаляются: пользователей пока нет (решение 06.11.2026).

Условие **жёсткое**: роль «мимо» отклоняет вакансию.

## Три слоя

1. **Бриф** — профроли и фразы.
2. **Поиск и отсев** — запросы к источникам по ролям или фразам, затем проверки всех условий брифа.
3. **Ранжирование по релевантности** — позже, в эту спеку не входит.

## Трансляция брифа в источники

| Источник | Что передаётся | Как |
|---|---|---|
| HH | роли и фразы | `hh.ru/search/vacancy?professional_role=…&text=…`; несколько ролей — через «или» |
| Getmatch | только роли | через специализации Getmatch (параметр `sp`); фразы Getmatch не ищет |
| ATS | только фразы | Greenhouse, Workable, Workday ищут текст сами; остальные доски обходятся целиком |

**Getmatch.** Специализаций 49, они смешивают роли и языки (`qa_auto`, `python`, `data_science`). Переход —
по ручной таблице «специализация Getmatch → роли HH», около 49 строк. Это разрешённое исключение из правила
«без ручных таблиц»: таблицу составляет агент, проверяет пользователь.

```
бриф «Тестировщик»  → sp=qa_auto&sp=qa_manual&sp=load_performance
бриф «Бухгалтер»    → специализаций нет → Getmatch не опрашивается,
                       в прогоне примечание «Getmatch: нет специализаций для ролей брифа»
```

Фильтр источника по роли только сужает поиск. Вердикт по роли он не даёт: вакансия из выдачи HH с ролью
«Программист» всё равно проходит классификатор.

## Классификатор роли

Классификатор — один из модулей обогащения, наравне с модулями на регэкспах (зарплата, география, формат,
релокация). Он добавляет факт «роль вакансии», проверка сравнивает этот факт с ролями брифа.

Запускается **один раз**, на ленте, по тексту, который в ней есть:

- HH — заголовок и сниппет;
- Getmatch — заголовок;
- ATS — заголовок и полное описание, если доска отдаёт его в выдаче.

На карточке классификатор не запускается повторно.

| Ответ классификатора | Вердикт | Итог |
|---|---|---|
| подходит | да | проходит |
| мимо | нет | отклонена; причина называет роль вакансии: «роль вакансии: Продавец-консультант» |
| не понять | — | «Может быть подходит», причина «роль не определена по заголовку»; карточка не грузится |
| не ответил (см. ниже) | неизвестно | «Подходит» с меткой «не проверено» |

- «Мимо» ставится только при явном несовпадении. Если сомнение — «не понять».
- **«Не понять» — осознанное исключение** из правила «неизвестно → Подходит». Классификатор видел текст и не
  смог решить. Загружать карточку и запускать классификатор по полному тексту дорого, особенно на HH (лимиты и
  блокировки), поэтому такая вакансия остаётся в «Может быть подходит» с фактами из ленты (решение 07.11.2026).

### Классификатор не ответил

«Не понять» — это ответ: классификатор прочитал текст и не смог решить. «Не ответил» — ответа нет вовсе,
вакансию никто не оценил:

- ошибка вызова: таймаут, сеть, ошибка сервера;
- лимит: отказ по частоте вызовов (429) или исчерпан бюджет прогона на классификатор;
- непригодный ответ: что-то кроме «подходит», «мимо», «не понять»;
- прогон прерван: вакансия из ленты сохранена, но до классификации не дошла.

Это отсутствие сведений, а не суждение, поэтому действует общее правило: «неизвестно» → «Подходит» с меткой
«не проверено». Вакансия не теряется из-за сбоя на нашей стороне. Повторного запуска на карточке нет.

- Ошибка вызова и непригодный ответ: перед тем как сдаться, вызов повторяется 1–2 раза.
- Лимит исчерпан: оставшиеся вакансии получают «Подходит, не проверено» **без загрузки карточек**. Иначе один
  исчерпанный лимит превратит остаток прогона в загрузку карточек всех вакансий подряд. В прогоне — примечание
  «роль не проверена у N вакансий: исчерпан лимит классификатора».
- Ошибка одной вакансии после повторов: «Подходит, не проверено», карточка грузится как обычно.
- Версий у роли нет: роль определяет только классификатор.

## Поток данных

```
СЛОЙ 1 · БРИФ
  профроли + фразы (обязательны оба) + остальные условия
        │
        ▼
СЛОЙ 2 · ПОИСК И ОТСЕВ
  2а. Запросы
      HH        роли + фразы
      Getmatch  только роли (через специализации Getmatch); нет специализаций → не опрашивается
      ATS       только фразы; доски без поиска обходятся целиком
        │
  2б. Лента
      HH        заголовок, компания, зарплата, место, формат, сниппет
      Getmatch  заголовок, компания, зарплата, места и форматы, релокация
      ATS       заголовок, компания, место; часто полное описание
        │
  2в. Обогащение по ленте → факты вакансии
      ├─ из структуры источника: зарплата, места, формат, релокация (Getmatch), дата…
      ├─ регэкспы по доступному тексту (сниппет HH, описание ATS): формат, зарплата, релокация…
      └─ классификатор (один раз, с повтором при ошибке): подходит / мимо / не понять / не ответил
        │
  2г. Проверки по фактам — все условия брифа, в т. ч. роль
      ├─ роль «мимо» или другое жёсткое «нет»     → отклонена, карточки нет
      ├─ роль «не понять» или мягкое «нет»         → «Может быть подходит», карточки нет
      ├─ классификатор не ответил: исчерпан лимит → «Подходит, не проверено», карточки нет
      └─ «Подходит» (в т. ч. «неизвестно», ошибка классификатора после повторов) ─┐
                                                    ▼
  2д. Карточка: полный текст и структура карточки
      (у ATS с полным описанием в выдаче шагов 2д–2ж нет: всё уже прочитано на ленте)
        │
  2е. Обогащение по карточке → новые факты
      ├─ структура карточки
      ├─ регэкспы по полному тексту: формат, релокация, зарплата, занятость…
      └─ классификатора нет: роль уже решена на ленте
        │
  2ж. Проверки заново по всем фактам → итог
      «Подходит» / «Подходит, не проверено» / «Может быть подходит» / отклонена
        │
        ▼
  выдача
        │
        ▼
СЛОЙ 3 · РАНЖИРОВАНИЕ (позже)
```

## Расхождения с кодом (07.11.2026)

- В брифе нет поля профролей; роль выводится из фраз через `match_profile` и `ROLE_SYNONYMS` (12 ролей,
  `src/selection/profile_matching.py`). Заменяется классификатором.
- `src/selection/checks/profile.py` даёт жёсткий вердикт по совпадению слов; «не понять» → «Может быть
  подходит» нет (кейсы 10, 12).
- Справочника ролей HH в репозитории нет (выгружен только для обсуждения).
- HH-парсер не передаёт `professional_role`, только текст (кейсы 3–4).
- Getmatch-парсер обходит общую ленту без `sp` и игнорирует фразы; таблицы «специализация → роли HH» нет
  (кейсы 5–6).
- Классификатора нет.
- Фразы и роли не обязательны; старые брифы не удалены (кейсы 1–2).
