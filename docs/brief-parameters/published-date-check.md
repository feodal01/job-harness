# Дата публикации: проверка свежести вакансии

Статус: согласовано 05.11.2026. Общее правило вердиктов —
в [README](README.md).

## Условие в брифе

Бриф хранит **период**: «за последние N дней» (решение 05.11.2026). При каждом запуске период пересчитывается
в дату: `сегодня − N дней`. Так сохранённый бриф через месяц по-прежнему ищет свежие вакансии.

Старые брифы с точной датой (`published_after`) сохраняют её, пока бриф не пересохранят.

Условие мягкое: «нет» даёт «Может быть подходит».

## Какая дата

- Проверяется **дата последнего обновления** вакансии, которую показывает источник, включая «поднятия» на HH.
  Поднятая вакансия значит, что работодатель ещё ищет человека.
- Если источник знает и дату первой публикации, она показывается меткой: «была опубликована 12.08.2026».
- Правка текста (`updated_at` в смысле «отредактировано») — не дата публикации.

## Несколько дат: берётся самая свежая

Даты ленты, карточки и разных источников не считаются версиями. Из всех дат вакансии берётся самая свежая
(решение 05.11.2026). Это исключение из правила версий: даты описывают разные моменты, а не спорят о факте.

```
лента HH       01.11
карточка HH    03.11   ← берётся
ATS            28.10
```

**Риск:** источник, который ставит дату «сегодня» при каждом показе (например, `datePosted` в JSON-LD,
сгенерированный при отрисовке страницы), сделает любую вакансию свежей. Защита — проверка при подключении
источника: если почти у всех вакансий источника дата совпадает с днём загрузки, его дата не принимается и
считается отсутствующей.

## Неточные даты

Относительные даты переводятся в дату от момента загрузки:

| Запись | Дата |
|---|---|
| «вчера», «yesterday» | загрузка − 1 день |
| «3 days ago», «3 дня назад» | загрузка − 3 дня |
| «30+ days ago» | загрузка − 30 дней (нижняя граница открытого интервала) |

«N+ дней назад» считается ровно N днями: насколько давнее, уже не важно (решение 05.11.2026). Поэтому:

- бриф «за последние 60 дней», «30+ days ago» → да;
- бриф «за последние 30 дней», «30+ days ago» → да;
- бриф «за последние 14 дней», «30+ days ago» → нет.

## Часовой пояс

Время вакансии переводится в часовой пояс брифа, сравниваются календарные даты. Если у времени вакансии пояс не
указан — пояс источника: HH — Москва, остальные — UTC.

Пояс брифа (решение 05.11.2026):

- фронт берёт пояс браузера (`Intl.DateTimeFormat().resolvedOptions().timeZone`, например `Europe/Moscow`) и
  записывает его в бриф один раз, при первом сохранении;
- дальше все запуски брифа (с фронта, через MCP, повторные) ссылаются на пояс из брифа; сам он не меняется,
  даже если бриф открыли из другого пояса;
- в брифе пояса нет (старый бриф, создан через MCP) → UTC, пока бриф не сохранят с фронта.

## Даты нет или она некорректна

Даты нет, она не разбирается или она в будущем → «неизвестно» → «Подходит» с меткой «не проверено».
Предположения по умолчанию нет.

## Расхождения с кодом (05.11.2026)

- Бриф хранит точную дату, периода нет (кейс 20).
- Из нескольких дат проверяется одна `published_at`, карточка просто заменяет ленту; самой свежей из разных
  источников нет (кейс 6).
- Даты первой публикации и метки нет (кейсы 5, 7).
- Дата берётся как календарный день в поясе самой записи, без перевода в пояс брифа (кейсы 8–10).
- В брифе нет поля часового пояса, фронт его не передаёт (кейсы 21–23).
- Относительные даты не переводятся (кейсы 11–14).
- Дата в будущем сейчас даёт «да» (кейс 16).
- Проверки источника на «дату при отрисовке» нет (кейс 18).
