# Релокация: проверка требования «нужна релокация»

Статус: согласовано 05.11.2026. Общее правило вердиктов — в [README](README.md). Формат и сведение вариантов —
в [work-format-check.md](work-format-check.md).

## Условие в брифе

У места брифа флажок «Нужна помощь с релокацией» (`rebuild`, b91f8fd). Подпись уже, чем правило: условием считается любая релокация, а не только помощь; подпись стоит сменить на «Нужна релокация». Место — куда кандидат едет. Откуда он едет, не важно. Условие мягкое:
«нет» даёт «Может быть подходит».

## Что считается релокацией

Релокация в любом виде — «да»:

- слово «релокация», «relocation», «relocate» без уточнений;
- виза или рабочее разрешение, билеты, жильё на первое время, бонус, полный пакет;
- «релокация за счёт кандидата» (Getmatch `relocation_candidate`): компания переводит человека, хоть и не платит;
- «переезд не компенсируем» при названной релокации — тоже «да», это не отказ от релокации.

«Нет» — только прямой отказ: «релокация не предоставляется», «no relocation», «без релокации».

Состав помощи, если назван, показывается меткой («виза, жильё»). На вердикт он не влияет.

## Куда — место варианта

Релокация — свойство варианта «место + формат», как география и формат. Проверяется по правилу «один вариант
целиком» из спеки формата.

- Релокация ведёт в место своего варианта. Бриф «Москва + нужна релокация» требует вакансию с релокацией
  в Москву. Отдельного правила для переезда внутри страны нет: это обычное совпадение места.
- Релокация без формата — вариант `{office, hybrid}` в месте релокации (решение по формату 05.11.2026).
- Удалёнка без исключений: подходит только вариант, где релокация названа («релокация + удалёнка из EU»).
  Просто «удалёнка из EU» — «нет». Поэтому флажок релокации на фронте не прячется при минимуме «удалёнка».

## Привязка текста к варианту

- Текст называет место («релокация на Кипр») — относится к варианту с этим местом.
- Текст места не называет («помогаем с релокацией») — относится ко всем вариантам вакансии, кроме удалённых.
  Удалённый вариант получает релокацию, только если о ней сказано прямо.

```
«Офис в Берлине или удалёнка по EU, помогаем с релокацией»
   вариант 1: Берлин, office         релокация да
   вариант 2: EU, remote_country     релокация нет (о ней не сказано)
```

## Молчание

Если источник ничего не говорит о релокации, ответ — «нет». Это осознанное отступление от общего правила
«неизвестно»: компании, которые помогают с переездом, обычно пишут об этом явно.

«Нет» ставится, только когда прочитан полный текст вакансии:

- HH и Getmatch — описание из карточки;
- ATS — полное описание из выдачи источника.

Без полного текста — «неизвестно». Такие вакансии попадают в выдачу: результаты прогона не фильтруются по
статусу карточки (`results_page`), а карточка может быть ещё не загружена, не найдена, не загрузиться из-за
ошибки или блокировки источника, или прогон прервался. Фронт сейчас статус карточки (`detail_status`) не
показывает.

## Версии

- Структура «релокация» и текст «релокация не предоставляется» — версии разошлись → «возможно».
- Структура «релокация» и текст «переезд не компенсируем» — обе версии «да» (это не отказ).
- Изменение во времени на том же этапе — берётся новое значение.

## Расхождения с кодом (05.11.2026)

- Getmatch `relocation_candidate` сейчас даёт «нет», по решению — «да» (кейс 6).
- Молчание сейчас — «неизвестно», по решению — «нет» при полном тексте (кейсы 22, 25).
- HH-текст требует слов о помощи («помощь с переездом», «relocation package»). Одно слово «релокация» сейчас
  не считается (кейсы 1–2). Это регэксп, одобренный 04.11 как временный до текстового enrichment.
- HH-текст ставит найденную релокацию всем местам вакансии, включая удалённые. По решению текст без места не
  относится к удалённым вариантам (кейс 20).
- ATS релокацию не читают вовсе.
- Сведение вариантов берёт релокацию лучшего варианта, а географию — сводную (см. расхождения в спеке формата).
- Фронт не показывает, что карточка не загружена.
- Флажок подписан «Нужна помощь с релокацией», по правилу — «Нужна релокация».
