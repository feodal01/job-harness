# Формат работы: проверка минимума формата

Статус: согласовано 05.11.2026. Общее правило вердиктов — в
[README](README.md). География — в [geography-places-check.md](geography-places-check.md). Релокация — отдельной
спекой.

## Шкала

Формат задаётся минимумом: подходит этот формат и всё, что свободнее.

```
office  →  hybrid  →  remote_country  →  remote_worldwide
офис       гибрид     удалёнка в зоне     глобальная удалёнка
строже ─────────────────────────────────────────▶ свободнее
```

| Минимум в брифе | Подходят форматы вакансии |
|---|---|
| не задан («Любой») | все, проверки нет |
| `office` | office, hybrid, remote_country, remote_worldwide |
| `hybrid` | hybrid, remote_country, remote_worldwide |
| `remote_country` | remote_country, remote_worldwide |
| `remote_worldwide` | remote_worldwide |

Шкала остаётся из четырёх значений, слияние двух удалёнок отклонено 05.11.2026. Без `remote_worldwide`
кандидат не может сказать «хочу именно международную удалёнку»: при месте «Москва» удалёнка по РФ проходила бы
сама. Само слияние потребовало бы переделать модель брифа, фильтры Getmatch, соответствие кодов HH и фронт.

На фронте (`rebuild`, b91f8fd) `remote_country` подписан «Удалённо по стране», хотя по смыслу это удалёнка в зоне (страна, группа,
регион). Подпись стоит поправить при переделке фронта.

## Место в брифе: откуда кандидат работает

Место в брифе всегда означает, где кандидат физически будет, когда работает. Формат и релокация задаются
на месте (группе мест), не на брифе целиком.

- На фронте от 1 до 5 мест. Страна обязательна, город — нет (флажок «вся страна», `scope: "country"`).
- Для удалёнки достаточно страны. Город нужен, когда важен офис или гибрид.
- Даже для глобальной удалёнки страна обязательна: исключения вакансии («кроме РФ») не с чем сравнить без
  места кандидата. Это осознанное требование.
- Для релокации место — куда кандидат едет. Откуда он едет, не важно.
- В брифе может быть несколько мест с разными минимумами. Каждое место брифа проверяется со своим минимумом.

Старые брифы: модель допускает 0–20 мест и общий `minimum_work_format` на весь бриф (устарел). Общий минимум
подставляется в места, где своего минимума нет. Бриф без мест проверяет только формат.

## Значения формата вакансии

- **`remote_worldwide`** — работать можно из любой точки мира. Исключения («по миру, кроме РФ и BY») формат не
  меняют: он остаётся глобальным, а исключения проверяет география против места брифа.
- **`remote_country`** — удалёнка с ограниченной зоной: страна, группа стран («из EU», «из СНГ») или регион.
  Зона должна включать место брифа (проверяет география). Если зона не названа — география «неизвестно».
- **`hybrid`** — регулярное присутствие в офисе: каждую неделю, «N дней в офисе».
- **`office`** — работа на месте работодателя. Сюда же относится разъездная работа: кандидат физически
  привязан к городу (решение 05.11.2026).
- **«офис или гибрид, не различить»** — множество `{office, hybrid}`. Так читается релокация без формата (ниже).
  Ответ на минимум: проходят все значения множества → да; ни одно → нет; иначе → неизвестно.

## Условия независимы

География и формат решаются каждое само по себе, ни одно не меняет ответ другого (решение 05.11.2026).

- Неизвестный формат не делает географию открытой. «Берлин, формат не указан» против брифа «Казань»: география
  «нет» (Берлин ≠ Казань), формат «неизвестно». Итог по варианту — «нет».
- Офис или гибрид, у которого место — страна, регион или группа, против города брифа: география «неизвестно»
  (город не назван), как в гео-спеке.
- Удалёнка с зоной-регионом сравнивается с регионом, а не только со страной: «удалёнка из Московской области»
  против «Казань» → география «нет».
- Исключение действует только на свой формат: исключение удалёнки не исключает офис, любая удалёнка = удалёнка.
  «Удалёнка везде, кроме РФ; офис в Москве» против «Москва, office» → вариант с офисом проходит.

## Формат и место — один вариант

Вариант — это место вакансии с его форматом. Формат одного места не переносится на другое.

```
Вакансия: «Офис в Москве или удалёнка по РФ»
   вариант 1: Москва,  office
   вариант 2: РФ,      remote_country

Бриф: Казань, минимум hybrid
   вариант 1: география нет (Москва ≠ Казань), формат нет
   вариант 2: география да (Казань ⊂ РФ),      формат да
Итог: да через вариант 2
```

### Сведение вариантов: один вариант целиком (решение 05.11.2026)

Итог вакансии берётся из одного варианта. Склеивать географию одного варианта с форматом другого нельзя.
Внутри варианта условия по-прежнему решаются независимо.

1. У каждого варианта считаются ответы всех условий брифа (география, формат, позже релокация).
2. Оценка варианта — худший из его ответов: нет < неизвестно = возможно < да.
3. Выбирается вариант с лучшей оценкой. При равенстве — тот, у которого больше «да».
4. Показываются ответы выбранного варианта.

**Пример 1. Склейка даёт ложное «да».**

```
Вакансия: «Офис в Казани или удалёнка из Армении»
Бриф:     Казань, минимум remote_country

                              география   формат   оценка
вариант 1: Казань, office        да         нет      нет
вариант 2: Армения, remote       нет        да       нет

по условиям отдельно:  география да (в. 1) + формат да (в. 2) → «Подходит»  ✗ ни один вариант не подходит
один вариант целиком:  оценка «нет» у обоих → формат нет → «Может быть подходит»  ✓
```

**Пример 2. Склейка прячет «не проверено».**

```
Вакансия: «Гибрид в Москве или удалёнка» (зона удалёнки не названа)
Бриф:     Москва, минимум remote_country

                                   география    формат   оценка
вариант 1: Москва, hybrid             да          нет       нет
вариант 2: удалёнка, зона неизвестна  неизвестно  да        неизвестно

по условиям отдельно:  география да (в. 1) + формат да (в. 2) → «Подходит» без метки  ✗
код сейчас:            география да (в. 1) + формат неизвестно (в. 2)                ✗ тоже склейка
один вариант целиком:  вариант 2 → география неизвестно, формат да → «Подходит, не проверено»  ✓
```

## Альтернативы и версии

- **Альтернативы** — варианты на выбор в одном высказывании: список кодов в одном поле (HH
  `[ON_SITE, REMOTE]`), «офис или удалёнка». Условие проходит, если подходит хотя бы один вариант.
- **Версии** — всё остальное: разные источники, разные поля или разные фразы одного текста называют разный
  формат для одного места. Каждая версия отвечает на минимум отдельно, вердикт — по общему правилу: все «да» →
  да, все «нет» → нет, разошлись → «возможно».
  - HH `REMOTE` (по умолчанию в стране) и текст «по всему миру» — две версии: и формата, и географии.
  - HH `[HYBRID]` и текст «work from anywhere» — две версии формата.
  - Текст «гибрид, 2 дня в офисе» и в другом абзаце того же текста «работайте откуда угодно» — тоже две версии.
- **Изменение во времени** на том же этапе (лента позже показывает другой формат) — берётся новое значение.

## Удалёнка с выездами (малозначимо для продукта сейчас)

- Регулярное присутствие (каждую неделю, «N дней в офисе») — hybrid.
- Редкие выезды («раз в квартал на офсайт», «командировки») — формат остаётся удалёнкой, ставится метка
  «есть выезды». Это не противоречие и не повод для «возможно».

## Формат не указан

Ни один источник не назвал формат → «неизвестно», вакансия идёт в «Подходит» с меткой «не проверено».
Вывод «раз не сказано, значит офис» не делается. Формат дочитывается из текста на этапе enrichment.
География при этом проверяется как обычно (раздел «Условия независимы»).

## Строгость условия

Минимум формата — мягкое условие: «нет» даёт «Может быть подходит», а не отклонение.

## Часовой пояс (данные, без проверки)

Поля в брифе нет. Пока записываем только данные:

- **Место.** В GeoNames `cities15000` у города есть часовой пояс IANA (`Europe/Moscow`). В `cities.sqlite` его
  нужно добавить при сборке справочника. Смещение от UTC с учётом летнего времени считает `zoneinfo`, ручных
  таблиц нет. У страны поясов может быть несколько (РФ — 11), поэтому у места «вся страна» пояс — диапазон.
- **Вакансия.** Ограничение «UTC+2…+5», «пересечение с Москвой не меньше 4 часов» — отдельный факт с диапазоном
  смещений и источником. Пока не проверяется и показывается меткой.
- **Будущая проверка.** Диапазон поясов места брифа пересекается с допустимым диапазоном вакансии. Работает то
  же правило версий.

## Расхождения с кодом (05.11.2026)

- HH `FIELD_WORK` сейчас даёт неизвестный формат, по решению — office (кейсы 18–19).
- Неизвестный формат держит географию открытой: другая страна или город дают «неизвестно», а не «нет»
  (`selection/checks/places/geography.py`, `legacy.py`). По решению — «нет» (кейс 40).
- Удалёнка сравнивается только по стране, зона-регион не проверяется (кейсы 36–37).
- Версии формата не дают «возможно» (кейсы 48, 51–53). Текст «по всему миру» сейчас заменяет HH `REMOTE` или
  добавляется к HH-формату как альтернатива (`hh/enrichment/__init__.py`), а по решению это отдельная версия.
- Релокация Getmatch без формата сейчас даёт неизвестный формат, по решению — `{office, hybrid}` (кейсы 22, 42).
- Переходный путь (`legacy.py`) раздаёт форматы вакансии всем местам без формата — это перенос формата между
  местами.
- Сведение вариантов в коде берёт географию из одного варианта, а формат из другого
