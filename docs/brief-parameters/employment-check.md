# Занятость: проверка вида работы и нагрузки

Статус: согласовано 05.11.2026. Общее правило вердиктов — в
[README](README.md).

## Две независимые оси

| Ось | Значения |
|---|---|
| Вид работы | найм (штат), проект / контракт, стажировка, волонтёрство |
| Нагрузка | полная (full-time), неполная (part-time) |

У вакансии всегда есть обе оси. Например, «контракт, full-time» — это вид «проект», нагрузка «полная».

## Бриф

Одна группа галочек: полная, неполная, проект / контракт, стажировка, волонтёрство. Галочки делятся по осям
(решение 05.11.2026, трактовка I):

- внутри оси — «или»: «полная + неполная» значит любая нагрузка;
- между осями — «и»: «полная + проект» значит проект на полный день;
- ось без галочек ничего не ограничивает;
- ни одной галочки — проверки нет.

```
Бриф: полная + проект
   нагрузка ∈ {полная}   И   вид ∈ {проект}

Вакансия HH «полная» (вид по умолчанию — найм)
   нагрузка полная → да
   вид найм        → нет
Итог: нет
```

Условие мягкое: «нет» даёт «Может быть подходит».

## Значения по умолчанию

Если ни один источник и ни один текст ось не назвал, берётся значение по умолчанию: **вид — найм, нагрузка —
полная** (решение 05.11.2026).

Это предположение на случай отсутствия сведений, а не версия. Как только какой-либо источник или текст называет
значение оси, значение по умолчанию отбрасывается и в подсчёте версий не участвует. Так HH `FULL` и текст
«проект на 3 месяца» дают вид «проект», а не «возможно» (кейс 23).

Значение по умолчанию не ставится, если источник что-то назвал, но перевести это нельзя (schema.org `OTHER`).
Тогда ось «неизвестно».

## Вердикт

1. Для каждой оси, где в брифе есть галочки, — ответ по общему правилу версий: совпало с одной из галочек → да.
2. Итог условия — худший ответ осей: нет < неизвестно = возможно < да.

## Альтернативы и версии

- **Альтернативы:** «полная, возможна неполная», список `["FULL_TIME", "PART_TIME"]` в одном поле. Ось проходит,
  если подходит хотя бы одно значение.
- **Версии:** HH-поле «полная» и текст «part-time, 20 часов в неделю» (без «или») → «возможно».
- **Изменение во времени** на том же этапе — берётся новое значение.

## Источники

| Источник | Значение | Вид | Нагрузка |
|---|---|---|---|
| HH `employmentForm` | `FULL` | найм (по умолчанию) | полная |
| | `PART` | найм (по умолчанию) | неполная |
| | `PROJECT` | проект | полная (по умолчанию) |
| | `INTERNSHIP` | стажировка | полная (по умолчанию) |
| | `VOLUNTEER` | волонтёрство | полная (по умолчанию) |
| HH `civilLawContracts` | ГПХ, самозанятость, ИП | не ось — метка формы оформления | — |
| schema.org `employmentType` (ATS, Getmatch JSON-LD) | `FULL_TIME` | — | полная |
| | `PART_TIME` | — | неполная |
| | `CONTRACTOR`, `TEMPORARY` | проект | — |
| | `INTERN` | стажировка | — |
| | `VOLUNTEER` | волонтёрство | — |
| | `PER_DIEM` (подённая оплата, работа по вызову) | — | неполная (решение 05.11.2026) |
| | `OTHER` | неизвестно | неизвестно |
| Любой источник | ничего не сказано | найм | полная |

«—» значит, что значение ось не задаёт: берётся из другого значения списка или по умолчанию. Список
schema.org может содержать несколько значений сразу: `["FULL_TIME", "CONTRACTOR"]` — проект на полный день.

Стажировка не связана с опытом и грейдом: это вид работы, опыт — отдельный параметр брифа.

## Расхождения с кодом (05.11.2026)

- Вакансия хранит один список `employment`, оси смешаны. Нужны две оси.
- Проверка — пересечение списков без осей (`selection/checks/employment.py`): кейсы 5, 8, 9, 11, 12, 19 сейчас
  дают другой ответ.
- Молчание сейчас — «неизвестно», по решению — найм и полная (кейсы 2, 3, 14).
- ATS переводятся ручной таблицей (`ats/normalization.py`), а не словарём schema.org. `TEMPORARY`, `PER_DIEM`,
  `OTHER` не распознаются.
- На фронте галочка `part_time` подписана «Частичная», по решению — «Неполная».
- Getmatch занятость не читает (кейс 22).
- HH `civilLawContracts` не читается (метка, кейс 24).
- Версий занятости из текста нет (кейсы 15–17, 23).

## Без галочки «Штат» (решение 05.11.2026)

В брифе нет галочки для вида «найм», и она не добавляется: пришлось бы разбираться в юридических вариантах
найма. Следствие принято: бриф «полная» пропускает и проект на полный день (кейс 5).
