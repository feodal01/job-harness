# Источники брифа: правила

Бриф не хранит список источников. Он хранит правила, а список собирается при каждом запуске
из реестра источников и каталога компаний (Supabase, с сессией пользователя). Так новые доски
каталога попадают в поиск сами, а каталог не копируется в бриф.

## Поля `search.source_rules`

| Поле | Значение |
|---|---|
| `mode` | `auto` — все поддерживаемые источники по типам и местам брифа; `selected` — только `include` |
| `groups` | Типы для `auto`: `aggregator`, `it_board`, `company_site`, `telegram`. Не задано — все типы |
| `include` | Добавить к правилам: id источника (`hh_ru`, `ats:lever:airslate`) или компанию `company:<uuid>` |
| `exclude` | Убрать после правил: те же два вида элементов |

По умолчанию (`search` или `source_rules` не заданы) — `auto` со всеми типами, включая сайты
компаний: смысл продукта в массовом поиске.

Компания хранится по UUID каталога, а не по id доски: адрес доски может смениться, UUID — нет.
При запуске компания раскрывается во все её поддерживаемые доски в каталоге на этот момент.

`include` и `exclude` — до 1000 элементов каждый. Это предел размера брифа, а не поиска:
сколько источников даст `auto`, решает каталог.

## Раскрытие при запуске

1. Страны — коды стран из `filters.locations`. Для `auto` берутся источники, чьё покрытие
   включает хотя бы одну страну брифа. Покрытие неизвестно (доски, сбой справочника HH) —
   источник участвует.
2. `include`: источники по id, компании — их доски из каталога.
3. `exclude`: убирается источник с этим id; `company:<uuid>` убирает доски этой компании.
4. Без входа или при сбое каталога доски не участвуют, причина видна в запуске, остальные
   источники ищут. Ошибка — только если искать не по чему.

Запуск может передать свои `source_rules` — они заменяют правила брифа для этого запуска.

## Снимок в запуске

`request` запуска хранит:

- `brief` — все параметры брифа на момент запуска: название, текст, запросы, фильтры, `search`
  (хранилище запусков сохраняло его и раньше);
- `source_rules` — правила, по которым собран список;
- `resolution` — страны, состояние каталога, сколько источников подошло и сколько убрано `exclude`;
- `sources` и `skipped` — что искали и что пропустили с причиной.

Строки каталога, по которым не искали, в запуск не попадают.

## Предпросмотр и поиск (для диалога 8о)

Правила в форме могут быть ещё не сохранены, поэтому оба метода принимают их в теле вместе
со странами мест: `{source_rules, countries}`.

- `POST /api/v1/sources/preview` — для каждого типа `available` (поддерживаемые, покрывают
  страны) и `selected` (войдут в поиск), `total`, `excluded`, каждый элемент `include` и
  `exclude` с названием и статусом (`included`, `excluded`, `missing` с причиной) и
  `catalog.rows` — строк в каталоге. Каталог читается один раз, а раскрывает правила тот же
  код, что и запуск. Ничего не осталось — ответ с нулём, а не 422.
- `POST /api/v1/sources/search` — `{…, name, groups, page, page_size}`: найденные источники с
  `participation` (`included`, `excluded`, `not_selected`, `not_covered`, `unsupported`),
  пояснением и `rule_item` — что положить в `include`/`exclude` (`company:<uuid>` для сайта
  компании). Неподдерживаемые тоже находятся, `rule_item` у них нет.
- MCP: `preview_sources` (с `name` — ещё и поиск).

Без входа оба метода отвечают по встроенным источникам, сайты компаний — нули и
`catalog.status`. Выключателя «подключать новые источники» нет: в `auto` новые источники,
подходящие под правила, подключаются сами.

## Переход

Пока диалога 8о нет, форма брифа показывает только встроенные источники и при сохранении
не теряет остальное. Галочки показывают, будет ли встроенный источник в поиске. В `selected` они
меняют встроенную часть `include`, компании, доски и `exclude` остаются. В `auto` с исключениями
или типами отмеченный источник вне выбранных типов попадает в `include`, снятый — в `exclude`.
Правила по умолчанию: все галочки — правила по умолчанию, меньше — выбор. Форма не сохраняет
правила, по которым искать не по чему, и не требует запросов, если в правилах есть компании,
доски или сайты компаний.

Старое поле `search.sources` убрано. Миграция базы удаляет его из сохранённых брифов, и они
получают правила по умолчанию. Запрос с `sources` отклоняется (422).
