# Внедрение согласованной формы брифа

**Цель:** рабочий сервис показывает вариант «Единый лист» из
`/Users/user/Documents/Codex/2026-10-25/brief-form-design/brief-form-directions.html`
с последними правками пользователя. Все поля сохраняют реальные значения и управляют поиском.

**Устройство:** существующие HTML, редакторы чипсов/локаций и JSON-контракт брифа.
Отдельный `src/web/static/brief-form.css` отвечает только за форму, без изменения остальных экранов.
Бэкенд, сопоставление географии и алгоритмы отбора не меняются.

## Требования

Название брифа, запросы, источники, места/формат, условия вакансии, исключения,
параметры поиска и заметки — равноправные разделы с h2 и нейтральными разделителями.
Зарплата/валюта/период и опыт/дата компактны; опыт и зарплата нового брифа пусты.
Форматы: любой, глобальная удалёнка, удалёнка в стране, гибрид, офис; значения API прежние.
Под выбором формата — порядок свободы и смысл минимального формата.
Кнопка «Добавить локацию», максимум пять мест, в том числе вся страна.
Заметки непосредственно перед кнопками внизу. Списки запросов/исключений остаются чипсами.
Удалить постоянные перечисления источников и их лимитов, сохранив предупреждения о реально
неподдерживаемых выбранных условиях и блокировке источника. Лимиты редактируются в details.
Галка «Загружать профили работодателей» сохраняет название и поведение.

## Проверка рисков

Пустые поля и неподтверждённый город показывают ошибки рядом с контролом, в том числе в
закрытом details. Последняя фраза без Enter сохраняется. Смена страны сбрасывает города
только своего блока. Разные сохранённые лимиты источников не теряются. Сохранение без поиска
и отмена не создают запуск. Обработка ошибки запуска сохраняет бриф и показывает причину.

## Surprises & Discoveries

Текущие поля уже передают null для пустой зарплаты/опыта, а чипсы включают неподтверждённый
Enter-ом текст. Это поведение необходимо сохранить. Общие пустые лимиты могут означать разные
ранее сохранённые ограничения; удаление пояснений не должно менять значения запроса.

## Ошибка нажатия на город в WebKit — 0.9.2

Сценарий пользователя «Россия → моск → нажатие Москва» воспроизведён в WebKit: mousedown
вызывал focusout с relatedTarget=null, список скрывался до mouseup/click, город не выбирался.
В Chrome фокус переходил на кнопку и прежняя проверка проходила. Предыдущее покрытие только
Chrome было недостаточным.

При mousedown на варианте списка теперь сохраняется фокус до click. Логика выбора и реального
закрытия при уходе из поля не меняется. Браузерная регрессия сохранена в
`tests/browser/city-picker.js`: частичный ввод «моск», выбор мышью/касанием, выбор всей страны,
добавление второго города, Escape/внешний клик, сохранение и повторное открытие брифа.
Тест запускался через Playwright CLI run-code на отдельном сервисе 8868 и настоящем справочнике.
До исправления WebKit падал на отсутствии чипса Москвы; после — Chrome, WebKit desktop
и WebKit с касаниями проходят. Полный pytest: 971 passed, Ruff/Mypy/JS/checksum успешны.
События до исправления: `/tmp/city-click-webkit-events.txt`, проверки: `/tmp/city-picker-regression-*`.

Основной сервис обновлён: `9c1acd008cb744b98171f57682c7b57c` → `cee9ed79a8c04740a8a6949e02428fe9`. Все 25 брифов сравнены и сохранены.
