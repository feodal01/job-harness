# Сервисы приложения и независимая география

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Отделить операции приложения от HTTP и обслуживать подсказки городов локально, без HH.

**Architecture:** API вызывает сервисы брифов, вакансий, запусков, источников и географии. Поисковый движок и адаптеры остаются отдельными компонентами; SQLite хранится через существующий Store. Пользовательская география читает поставляемый с проектом снимок GeoNames, а адаптер HH сам переводит выбранное место в свои параметры.

**Tech Stack:** Python, FastAPI, SQLite, существующий интерфейс JavaScript; без новых runtime-зависимостей.

**Spec:** Согласованные требования в текущем обсуждении от 08.10.2026; `docs/product-spec-v2.md` для сохранения поведения поиска.

## Global Constraints

- Работа в текущей main, без коммита и push; сохранять существующие файлы и пользовательскую базу.
- Реальную доступность сайтов не проверять: это вторая очередь, дизайн проверки ещё не определён.
- Не обходить сайты работодателей и не искать контакты.
- Сохранить URL и данные операций брифов, вакансий и запусков.
- Не вводить сетевой резервный путь для локальной географии.
- Нативная география HH остаётся в адаптере. Старые HTTP-ручки нативных справочников убираются; интерфейс их не использует.
- Снимок географии охватывает текущие 32 страны; исходник GeoNames cities500, названия и регионы, атрибуция и воспроизводимая сборка.

## Review Focus

- Подсказки работают при недоступном HH и без его адаптера.
- Русские и латинские названия, одноимённые города и регионы не теряются.
- Выбранный локальный город корректно передаётся в поиск HH, без HH ID в брифе.
- Ошибка пересчёта брифа не оставляет частично сохранённые условия/оценки.
- Список источников не делает сетевых проверок и не обещает доступность сайтов.
