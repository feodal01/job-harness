# Иерархия приложения и эксплуатационные контракты

**Goal:** Закрыть восемь замечаний аудита: структура, логирование, модели, хранение, зависимости, ошибки, API и жизненный цикл.

**Architecture:** В корне src остаются точки входа и зависимости. core — настройки и логирование; models — предметные данные; schemas — HTTP; selection — правила отбора; db — соединение и отдельные репозитории; network — запросы источников; web — HTML/CSS/JS. Сервисы получают узкие интерфейсы репозиториев и исполнителя поиска. Подключение SQLite и общий transaction принадлежат одному Database; репозитории разделяют его.

**Tech Stack:** Существующие FastAPI/Pydantic/SQLite/httpx, стандартный logging; без новых внешних сервисов.

**Spec:** Восемь пунктов аудита в предыдущем ответе и разрешение пользователя «действуй, закрой все эти проблемы».

## Constraints
- Текущая main, без коммита и push. Базовая копия кода и БД: /tmp/hh-architecture-before.
- Сохранить URLs, сохранённые данные и интерфейс. Проверки доступности источников по-прежнему отложены.
- Данные schema v8 уже преобразованы. Удалить старые миграции и их тесты; заменить проверками новой БД, v8, отказа для старой/будущей БД без изменений и утечек блокировки. Старые исторические снимки запусков остаются неизменными данными.
- Не вводить ORM, абстракции ради абстракций, совместимые импорты старых путей, Sentry/Logstash или новые сетевые зависимости.
- Логи: stdout, управляемый уровень и формат; request_id/run_id/source_id/stage; без тел запросов, текстов брифов и заголовков авторизации.

## Ownership

- Logging worker: только src/core/logger.py, observability.py, настройки logging в core/config.py, tests/test_logging.py; root подключает middleware и lifecycle.

## Review focus
- Исторические снимки данных читаются и не перезаписываются при запуске.
- Схемы ответов не теряют поля вакансий, профилей, происхождения и навигации.
- Техническая ошибка не маскируется под 404/409/422.
- Контекст логов из параллельных запросов/источников не смешивается и не раскрывает текст брифов.
- Ошибка startup/close одного ресурса не оставляет заблокированную БД или живой HTTP-клиент.
