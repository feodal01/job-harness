# Перенос независимых ATS-парсеров


## Purpose / Big Picture


Текущая задача после уточнения пользователя 11 октября 2026: перенести ATS-парсеры из `qa-job-harness` в текущие интерфейсы `hh-search-prototype`. Каждая ATS имеет отдельный пакет. Парсер получает данные конкретной доски и возвращает нынешние `Vacancy` / `SearchPage`; новый работодатель на поддержанной платформе не требует изменений Python-кода.

Связывание с таблицей компаний и инструментом `list_companies` исключено из этого этапа. Здесь нет изменений Supabase, выбора компаний в API/MCP/UI, `company_catalog`, динамического реестра запусков или схемы хранения. Автоопределение ATS отложено и в будущем будет отдельным модулем. Сейчас вызывающий код явно импортирует фабрику нужной ATS.

## Surprises & Discoveries


У донора один `plugins/job-harness/src/job_harness/v2/runtime/sources/companies/ats/source.py` на 7050 строк объединяет 213 компаний, правила разных платформ, чужие контракты и управление запросами. Прямое копирование файла нарушает границы текущего приложения.

Некоторые интерпретации зависят от работодателя: у CoinsPaid есть отдельный список городов, у Outschool — определение офиса по отсутствию remote, у AppFollow — обрезка даты и переключение режима карточки. Эти настройки и эквивалентные правила в JSON или БД не переносятся. Прохождение старых тестов не доказывает универсальность.

Из 213 конфигураций успешные фикстуры есть у 81. У части платформ есть только один работодатель с сохранённым ответом; отсутствие независимых примеров нужно указывать. Фикстуры донора иногда минимизированы: число записей в них не равно текущему объёму живого сайта.

Workday использует POST с JSON и меняющимся offset. Старый `ListingWalker` сравнивал только URL и считал следующую страницу повтором. Расширение существующего сетевого контракта необходимо для переноса этого парсера; отдельный HTTP-клиент внутри Workday не нужен.

В целевом проекте `src/parsers/interfaces.py` определяет компоненты источника. `src/parsers/registry.py` регистрирует обычные HH/Getmatch. Для текущей задачи его не менять: новые фабрики доступны по прямому импорту. `src/services/companies.py`, Auth, HTTP API, MCP и UI находятся вне текущего изменения.

## Plan of Work


Каждый пакет экспортирует `create_adapter(board: Board, settings: RequestSettings | None = None) -> SourceAdapter`. `Board(url, company)` содержит только исходный адрес и имя для отображения. Сам модуль ATS проверяет поддержанный адрес и получает slug, регион или tenant/site по правилам собственной платформы. Никакой перебор парсеров или каталог работодателей не используется.

Перенести Ashby, Greenhouse, Lever, Workable, BambooHR, Recruitee, SmartRecruiters, Breezy, Huntflow, Personio, Teamtailor, Join, DreamJob, Jobvite, JazzHR, iCIMS, Comeet, Y Combinator, Taleo, SuccessFactors и Workday. JSON-LD — общая операция разбора стандартного описания, а не универсальный обход произвольного сайта.

Общие модули `models.py`, `common.py`, `normalization.py`, `jsonld.py` содержат только повторяющиеся механизмы: вход доски, подготовку полной ленты, создание SourceAdapter, строгую проверку JSON и нормализацию явных значений. Правила конкретной платформы остаются в её пакете. Имена компаний, их домены, списки городов, секций и исправлений не попадают в исполняемые правила. Константы схемы ATS, ключи JSON и стандартные enum-значения допустимы как описание формата.

Парсер сразу создаёт Vacancy. HTML проходит существующий `parse_rich_text`, сохраняются текст и очищенная разметка. Дата изменения не становится датой публикации. Неизвестная зарплата, страна или город остаются неизвестными; исходный текст хранится как факт источника. Отсутствие remote не означает офис. Текущая модель использует `remote_country` для явного remote без доказанного worldwide; неизвестная страна остаётся None, принадлежность компании к стране не подставляется.

Полная лента использует `query=ignored` и один начальный запрос; локальный отбор остаётся движку. Workday использует нативные фразы и POST. Пагинация всех платформ возвращает `SearchPage.next_requests`; ни один парсер не исполняет HTTP, asyncio.gather, повторные попытки или собственный scheduler. Поддержанные карточки используют существующий VacancyDetails.

Расширение сети ограничено read-only POST списка вакансий: тот же limiter, retry, breaker и проверка разрешённых хостов. POST 307/308 сохраняет метод/тело, 303 переходит на GET, неоднозначные 301/302 завершаются ошибкой. JSON страницы входит в ключ повтора. Никакого special case по имени Workday в транспортном слое.

## Concrete Steps


Тесты отдельных платформ: `tests/parsers/ats/test_<platform>.py`; реальные ответы: `tests/fixtures/ats/<platform>/` с исходными метаданными. Сравнивать поля с самим ответом, а не переносить ожидания донора с индивидуальными эвристиками. Синтетические проверки обозначать как проверки контрактов/независимости, не как реальные ответы сайта.

После реализации выполнить из корня целевого репозитория:

    uv run pytest -q tests/parsers/ats tests/test_ats_requests.py tests/test_ats_contracts.py
    uv run ruff check src scripts tests benchmarks
    uv run mypy
    uv run pytest -q
    git diff --check

Новые модули не подключать к работающему сервису и таблице. Для bounded live-проверок использовать явные адреса нескольких публичных досок, сохранять исходные ответы и условия запроса. Ограничения доступа фиксировать отдельно от ошибок разбора. Живую выдачу не использовать как стабильный regression snapshot без сохранения ответа.

## Validation and Acceptance


Каждая из 21 платформы имеет отдельный импортируемый адаптер, совместимый с текущими интерфейсами. Ни один пакет не импортирует job_harness, detector, сервис компаний, HTTP-клиент, БД или чужой пакет ATS. Стандартный JSON-LD и общие нормализаторы допускаются.

Несколько работодателей проверяются там, где есть реальные сохранённые примеры; для подтверждения работы вне старого списка нужен хотя бы один новый работодатель. Где такой проверки нет, отчёт прямо ограничивает утверждение проверенными форматами. Добавление нового работодателя требует только входных данных, а изменение его отображаемого имени не меняет факты вакансий. Нет индивидуальных переключателей поведения в конструкторе.

Проверить значимые поля, HTML, реальные ссылки, идентичность доски, поддержанные карточки, пагинацию и отсутствие выдуманной географии. Пустая корректная выдача и сломанная структура различаются; отсутствие реальной пустой фикстуры явно отмечается. По всем включённым платформам фиксируются количество и происхождение примеров, без заявления о проверке всего живого каталога.

Общий POST проверяется через синтетический источник и настоящий SearchEngine с тестовой SQLite: страницы одного URL с разными телами собираются, повтор одинакового тела останавливается, фильтры и сохранение остаются рабочими. Старые GET-источники проходят прежние тесты. Supabase, MCP и обычный список источников сохраняют текущую конфигурацию.

## Idempotence and Recovery


Эта задача не меняет Supabase или рабочую SQLite и не запускает массовый поиск. Все тестовые базы находятся во временных каталогах pytest. Парсеры и сохранённые публичные ответы можно проверять повторно без пользовательской сессии. Не сбрасывать чужие изменения, не выполнять commit/push или установку плагина в этом этапе.

## Interfaces and Dependencies


Сохраняются SourceAdapter, Search, SearchPage, SearchPlan, VacancyDetails и Vacancy. Новые поля SearchRequest: `method: Literal["GET", "POST"]` и `json_body: dict[str, JsonValue] | None`; свойство identity включает тело. Network.fetch исполняет поисковый запрос через тот же внутренний транспорт, а Network.get обслуживает GET-карточки и подготовку. Зависимости Python остаются существующими; чужой runtime и новые сетевые библиотеки не добавляются.

Изменение от 2026-10-11: прежний план подключения общего каталога заменён после прямого ограничения пользователя. В текущей работе только перенос ATS и минимальная поддержка их запросов.
