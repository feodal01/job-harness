# Локальный API географии на SQLite

24.10.2026. Реализовано; проверено в сервисе, браузере и установленном плагине.

## Результат

Сервис ищет города в `cities15000` со всеми имеющимися языковыми вариантами, без внешних запросов.
Используем существующий `GET /api/v1/geography/cities`: его уже вызывают веб-интерфейс
и MCP-инструмент `find_cities`. Исправление опечаток, перевод географии для ATS
и постфильтрация вакансий — отдельные задачи.

## Названия стран для пользователя

Сейчас настройки языка нет: **названия стран по умолчанию английские, `locale=en`**.
`GET /api/v1/geography/countries` возвращает `{"code":"DE","name":"Germany"}` среди остальных стран.
Параметр `locale` необязательный; например, явный `locale=ru` даст название `Германия`.
Интерфейс показывает и ищет по `name`, в запрос города передаёт `code`.
`Германия`, `Germany`, `Deutschland` обозначают один ISO-код `DE`;
будущая смена языка не меняет сохранённые условия.

Названия берутся из поставляемых данных Unicode CLDR — готового набора названий для разных языков,
а допустимые коды — из ISO-каталога. Макрорегионы и служебные коды CLDR не становятся странами.
Список доступных языков определяется данными, не ручным списком RU/EN.
Для каждого поддерживаемого языка при сборке проверяется покрытие всего ISO-каталога;
неподдерживаемый `locale` получает явный `422`, а код страны не подставляется вместо названия.
Единый default `en` задаётся на стороне сервиса; MCP использует то же значение.
Веб-интерфейс пока может не передавать `locale`. Автоматического определения по браузеру,
`Accept-Language`, системе или языку диалога нет. Когда появится настройка языка, клиенты
начнут передавать её значение в существующий параметр `locale`; API переделывать не потребуется.
Переключатель языка и его хранение в эту фичу не входят.
`locale` влияет на подписи, но не ограничивает языки поиска городов.

Источник названий: [Unicode CLDR](https://cldr.unicode.org/translation/displaynames/countryregion-territory-names).

## Выбор и сохранение города

Форма завершается только при наличии **1–5 подтверждённых городов**. Страна без города и
произвольный введённый текст в этой версии не сохраняются как место поиска.
Добавление места, сохранение брифа и запуск поиска проверяют выбор GeoNames ID из подсказок.
Изменение текста или страны сбрасывает подтверждение. После выбора полного названия или добавления
места оно показывается в найденном написании: `Москва`, `München`, `กรุงเทพมหานคร`.
Язык `locale=en` не заменяет найденное название города английским.

Для подсказки `name` — полное совпавшее название из GeoNames, а не введённый префикс;
`ascii_name` — отдельное неизменяемое значение из поля `asciiname` исходной записи.
Сохранённое место содержит ISO-код `country`, английское `country_name_en`, GeoNames ID,
`city` в ASCII и отдельное `city_display_name` для восстановления пользовательского написания.
Например: `RU`, `Russia`, `524901`, `Moscow`, `Москва`.
Регион и идентичность места сохраняются для различения одноимённых городов.

Сервер проверяет принадлежность ID стране, существование выбранного варианта названия
и сам получает канонические поля из справочников. Переданные клиентом английские/ASCII-поля
не считаются доказательством корректного выбора. Одна строка без выбранного ID отклоняется
также при прямом HTTP/MCP-вызове. Сравнение мест опирается на коды/ID, не на отображаемую подпись.

**Проверка снимка:** у всех 34 160 записей `cities15000` поле `asciiname` непустое и состоит
из ASCII-символов. В проверенном английском CLDR есть названия для всех 249 кодов ISO-каталога.
Актуальное имя с английской языковой меткой есть только у 12 719 мест;
по решению пользователя каноническим именем города служит именно ASCII, а не предполагаемый перевод.
Сборка обязана повторять проверки полноты и завершаться ошибкой при пропусках.

## Где хранить

**`src/geography/data/cities.sqlite` внутри установленного Python-пакета**, открытие только
для чтения (`mode=ro`). Установочный пакет wheel сам сжимает содержимое и распаковывает при установке:
отдельный архив, копия в каталоге пользователя и распаковка при запуске не нужны.
Фактический файл занимает 58 130 432 байта (55,4 МиБ). В wheel он сжат до 20,1 МиБ;
весь wheel версии `0.6.0` — около 22,4 МиБ. Ранняя оценка 34/12 МиБ относилась
к упрощённому экспериментальному формату без всех рабочих индексов и региональных алиасов.

Пользовательская `$JOB_SEARCH_DATA_DIR/search.sqlite` остаётся отдельной базой.
Справочник обновляется вместе с плагином; миграции и резервные копии пользовательской базы его не затрагивают.
Путь определяется от установленного пакета, не от текущей папки.

## Контракт

`GET /api/v1/geography/cities?country=RU&text=санкт` возвращает список до 20 городов с `locale=en`:
`geoname_id`, `country`, `country_name_en`, `name`, `ascii_name`, `region`, `path`.
`name` сохраняет найденное написание, `ascii_name` предназначено для внутреннего сохранения.
Разные GeoNames ID не объединяются при совпадении названий.

Страна — назначенный ISO alpha-2 код; текст — 1–100 символов после нормализации.
Поиск точный и по началу названия: сначала точные совпадения, затем по населению.
Регистр и Unicode нормализуются, диакритика сохраняется. Нет совпадений — `200` и `[]`;
неверный ввод — `422`. `санкт петербург` находится; `санкт питрбург` пока не исправляется.
`/countries` получает полный ISO-каталог независимо от наличия городов в снимке.

## Отдельная задача: география вакансии и постфильтрация

Разделяются три операции: подсказки при вводе, нормализация географии вакансии
и сравнение с условиями пользователя. Нормализация означает приведение географических полей
источника к общим кодам и идентичности места. Для внутренней обработки HTTP не требуется.

Путь данных: адаптер источника читает его структурированные поля или данные страницы →
внутренний нормализатор получает выделенные географические факты → `src/selection/filtering.py`
сравнивает их с выбранными местами. Сейчас извлечение и нормализация находятся в
`src/parsers/normalization.py`, `src/parsers/ats/normalization.py` и адаптерах;
перераспределение этой логики требует отдельного плана.

Сырые HTML/URL не являются входом общего нормализатора. Разбор страницы остаётся у адаптера;
проверенные country/city/region и исходные значения сохраняются вместе. Результат может содержать
несколько мест, неизвестную или неоднозначную географию, отдельно — офис и допустимые места работы.
Сравнение возвращает совпадение, несовпадение или недостаточность данных.
Отсутствие города в `cities15000` само по себе не означает несовпадение.

Оба сценария могут использовать общий справочник и идентификаторы, но имеют разные контракты.
`cities15000` — ограничение списка подсказок, не универсальное покрытие географии вакансий.
API «страница → страна/город» в эту фичу не добавляется. Если потребуется внешнему клиенту,
HTTP-обёртка над внутренней нормализацией проектируется отдельно, без вызовов собственного HTTP из движка.

## Обнаруженное (Surprises & Discoveries)

До реализации публичный API загружал старый JSON и принимал свободный текст.
Теперь API использует SQLite; прежний JSON остаётся у старых функций нормализации вакансий.
Из 34 160 исходных строк `cities15000` исключена 21 строка с неназначенными ISO-кодами.
Для 249 стран есть полные подписи; города имеются в 243 из них.
В системе обнаружен зависающий экземпляр управляемого Python 3.12 в `~/.local/share/uv`.
Сборка и установленная проверка выполнены рабочим Python 3.12 из кэша плагина;
не менялись настройки или исполняемые файлы пользовательского Python.

## Решение (Decision Log)

24.10.2026: выбран файл внутри пакета вместо пользовательского каталога:
меньше копий и состояний запуска. Сохраняется существующий HTTP-маршрут.
По уточнению пользователя локализованные названия отделены от ISO-кодов; нормализация вакансий
и постфильтрация остаются внутренними операциями, отдельными от API подсказок.
Язык по умолчанию — английский; `locale` сохраняется для будущей настройки языка,
автоопределение и интерфейс выбора языка сейчас не добавляются.
По последнему уточнению город обязателен и выбирается из подсказок. Страна сохраняется английским
названием и ISO-кодом, город — ASCII-именем и GeoNames ID; найденная подпись хранится отдельно.

Версия поднята до `0.6.0`, чтобы новый клиент не использовал уже запущенный сервис
со старым контрактом. Пользовательская схема SQL не меняется: новые поля находятся в JSON брифа.
