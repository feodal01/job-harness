# Компактная форма брифа и списки чипсов

## Результат

Кнопки сохранения и отмены находятся в конце формы без закрепления при прокрутке.
Непосредственно перед ними — заметки. Центральная область шире; в локационном блоке
страна, город и формат стоят в одной строке на широком экране, на телефоне — друг под другом.
Города, вся страна, пять мест и независимые условия блоков сохраняют прежний смысл.
Поисковые фразы, исключённые компании и текст — чипсы с добавлением по Enter/кнопке,
удалением и восстановлением после сохранения. Незавершённый текст при сохранении не теряется.

## Контекст и решение

`src/web/index.html`, `app.js` и `location-editor.js` обслуживают форму, `app.css` — её вид.
Добавляется переиспользуемый `token-editor.js` для трёх списков. API и JSON брифа продолжают
принимать массивы строк; миграция данных не нужна. Ограничения 10 фраз по 500 символов,
50 исключений по 200 символов сохраняются. Запятые в названиях и фразах не разделяют чипсы.
Существующие проверки ошибок остаются, включая список с чипсами и пустым полем ввода.

Лимиты уже вычисляются движком из настроек источника и переопределений брифа. В `GET sources`
добавляется `default_limits`, полученный из реальных `SourceAdapter.settings`, включая env.
Не дублировать числа 50/2 и 2000/15 в JS. Подсказки показывают значения по умолчанию и
действующие значения с учётом сохранённых переопределений и редактирования общих полей.
Пустое поле использует настройки, существующие разные значения источников не теряются.

HH: вакансии — уникальные внутри источника текущего запуска, лимит на фразу. Страницы —
на каждую нативную поисковую ветвь фразы (география/удалёнка), не на весь запуск.
Getmatch игнорирует фразы при обходе, получает одну общую ленту с собственными лимитами.
Лимит вакансий считается до общего фильтра; подходящих результатов может быть меньше.
Алгоритм поиска и лимиты не меняются — меняется объяснение и отображение.

## Этапы и проверка

Добавить API-тест с нестандартными лимитами, затем поле ответа и сервис. Реализовать чипсы,
перенести заметки/действия, сделать сетку локации. Проверить браузером ввод Enter, удаление,
последний неподтверждённый Enter-ом текст, сохранение/повторное открытие всех трёх массивов,
красные ошибки, мобильную ширину 390 и порядок элементов. Проверить подсказки лимитов при
смене источников и сохранённых разных настройках. Запуск поиска перехватить в тестовом
браузере; рабочие брифы и реальные поиски для проверки не создавать.

Из корня репозитория: `.venv/bin/pytest -q`, Ruff, Mypy, `node --check` для изменённых JS.
Пересобрать плагин, выполнить `scripts/build_plugin.py --check`, проверить установленную
копию через MCP. Обновить работающий сервис только при отсутствии активных поисков,
проверить новый instance_id и сохранность брифов. Коммит/публикация не запрошены.

## Surprises & Discoveries

Слово «новых» в подписи не соответствует новизне в сохранённой базе: `SourceRun.seen`
учитывает текущий запуск, а сохранённые карточки повторно используются. Страничный лимит
применяется отдельно к каждой нативной ветви. Эти правила не следует упрощать до общего
числа страниц на фразу или обещанного количества подходящих вакансий.

## Decision Log

25.10.2026: переиспользуемый редактор массивов, без смены модели хранения. Отдельный
API-параметр defaults вместо ручных чисел в интерфейсе. Общее переопределение лимитов
сохраняет текущую семантику; разные сохранённые настройки источников показываются явно.

Ruff, Mypy (166 файлов), JS syntax и diff-check успешны. Браузер на изолированной БД:

копии подтвердил defaults, сохранение географии, перезапуск и авторизацию каталога.
