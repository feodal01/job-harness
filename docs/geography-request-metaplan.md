# География: метаплан подготовки запросов

Дата: 21.10.2026. Статус: предложение для обсуждения, не план реализации по источникам.
Область: выбор пользователя → разрешение места → нативные запросы. Постфильтрация вакансий исключена.
Основание: [продуктовая спецификация, §3.4](product-spec-v2.md#34-география-и-формат-работы),
[аудит географии](geography-review.md).

## Вывод и сложность

Маппинг страны по ISO — задача небольшой сложности. Город — средней, если строка служит поиском
конкретного места с подтверждением выбора. Произвольная строка без разрешения неоднозначности
делает задачу сложной и ненадёжной. Главная переменная — возможности каждого источника:
не всякая доска умеет фильтровать страну/город, даже когда эти поля есть у вакансии.

## Предлагаемый путь

`Страна ISO + строка города → подсказки → выбранное место → до 5 альтернатив → перевод для доски → запросы`

| Этап | Действие | Результат |
|---|---|---|
| 1. Страна | Выбор полного каталога стран/территорий; проверка назначенного ISO alpha-2 кода | Однозначная страна, например RU. Отсутствие городских данных не делает код невалидным |
| 2. Поиск города | Искать введённый текст только внутри страны, включая RU/EN алиасы | Кандидаты с уточнением региона; несколько кандидатов требуют выбора, отсутствие кандидатов показывается явно |
| 3. Фиксация места | Сохранить идентичность выбранного города и его административное уточнение; название оставить подписью | Страна ISO + необязательное однозначное место. Без города — вся страна |
| 4. Перевод для источника | Получить допустимые географические значения API/формы/доски; сопоставить с выбранным местом | Конкретный source ID, код, точная допустимая метка или явная невозможность перевода |
| 5. Сборка запросов | Объединить до пяти мест через OR; если source OR не умеет — отдельные запросы | Набор нативных запросов с указанием, какое место и ограничение выражает каждый |

Строку нельзя сразу разослать всем источникам как `city`: источники могут ожидать ID,
название офиса, значение select или JSON-фасет. Отправленное слово не доказывает применение фильтра.

## Два разных сопоставления

**Страна пользователя → страна источника.** Если источник принимает ISO, перевод обычно прямой
с учётом документированного формата значения. Если принимает собственный ID, он получается
из справочника источника. Если доступны только подписи, они разрешаются через общий справочник
названий стран; неразрешённая или групповая метка не выдаётся за конкретную страну.
Не нужны вручную заполненные независимые списки стран в каждом адаптере.

**Выбранный город → место источника.** Используются страна, известные алиасы и административное
уточнение; при наличии — идентификаторы/координаты справочника. Первое совпавшее имя или самый
населённый вариант не являются достаточным доказательством. Источник может предлагать офис,
агломерацию или группу регионов вместо города: это другое ограничение.

Общая идентичность города хранится отдельно от ID HH/доски ATS. GeoNames может быть основой
общего справочника; текущий снимок нужно расширять и сохранять идентификаторы, которые сейчас удаляются.
Неполное покрытие небольших населённых пунктов показывается явно. Универсальный разбор адресов не требуется.

## Разные источники — одна граница ответственности

| Контракт источника | Как готовится запрос | Сложность |
|---|---|---|
| Прямые country/city-параметры с установленным смыслом | Привести значения к контракту и проверить, что фильтр применяется | Низкая–средняя |
| Поисковый справочник географии с ID | Найти страну/город, разрешить неоднозначность, использовать найденный ID | Средняя |
| Настраиваемые офисы/локации/фасеты работодателя | Прочитать значения конкретной доски, сопоставить и сохранить точность ограничения | Средняя–высокая |
| Только широкие категории или отсутствие геофильтра | Сообщить границу возможностей; точный городской запрос нативно недоступен | Ограничение источника, а не сложность алгоритма |

Справочники доски можно кешировать с учётом источника, работодателя и версии/языка данных;
глобально переносить их ID между работодателями нельзя. Подбор значений до запроса не является
постфильтрацией вакансий и не требует обходить всю ленту вакансий.
Адаптер описывает параметры, HTTP выполняет существующий движок.

## Что возможно без постфильтрации

Подготовка сообщает по каждой выбранной географии: **точно выражено**, **выражено шире**,
**нет подходящего фильтра** или **место неоднозначно**. Точность означает установленный смысл
нативного фильтра, а не универсальную гарантию административных границ всех сайтов.
Проверяются значения формы/контракта и положительные/отрицательные запросы;
HTTP 200 или отражённая подпись не доказывают точность.

Рекомендуемое правило: широкий запрос не подменяет точный молча. В этом этапе он допустим
только как явно выбранный режим с отмеченным неприменённым условием. Если широкие результаты
не разрешены, соответствующая ветвь источника не запускается; остальные места/источники сохраняются.
Отсутствие применимого запроса показывается отдельно от «найдено 0 вакансий».

Город публикации/офиса и место, из которого разрешена удалёнка, различаются. По текущей продуктовой
модели remote может подходить для выбранного города без офиса в нём. Нативный фильтр города
не гарантирует такое соответствие: где источник не выражает remote-географию, ограничение остаётся
широким/неподдержанным. Точность всех результатов и полнота remote-покрытия без постпроверки не обещаются.

## Что конкретизировать следующим шагом

Сначала общий каталог стран, идентичность города, выбор до пяти мест и статусы подготовки.
Затем один общий контракт перевода места и проверки применимости. После этого — отдельные планы
по источникам: откуда читать справочник, что означает фильтр, как выразить OR и сохранить параметры
при пагинации. Проектирование локального отбора результатов остаётся отдельным этапом.

Проверяемые сценарии будущих планов: страна без города; два одноимённых города; RU/EN алиасы;
пять альтернатив; неизвестное место; широкий source-регион; отсутствующий фильтр;
устаревшее значение доски; сохранение географии на следующих страницах.
