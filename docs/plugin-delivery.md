# Доставка плагина Codex

`job-search` содержит MCP-сервер, поисковый движок, REST API и веб-интерфейс.
Поддерживаются macOS и Linux. Windows и упаковка для Claude в эту реализацию не входят.

## Установка

После публикации репозитория пользователь добавляет его Git URL в маркетплейсы
Codex, устанавливает **Job Search** и начинает новый чат. Codex сам получает код
плагина. Предварительное клонирование и `start.command` не нужны.

Для локальной разработки из корня этого репозитория:

```sh
codex plugin marketplace add "$PWD"
codex plugin add job-search@job-search
```

У текущего рабочего репозитория пока нет `origin` и первого коммита.
Публикация на GitHub ожидает адреса репозитория; установка из отдельного
Git-маркетплейса проверена через временный локальный HTTP-сервер.

## Запуск и остановка

Codex запускает MCP по stdio командой из `.mcp.json`. Обёртка `start-mcp.sh`
использует установленный `uv` или скачивает частную копию `uv 0.9.18` с официального
сайта. Затем получает Python 3.12 и зависимости по `uv.lock`. Нужны сеть и `curl`
для первой установки. Профили shell и системный Python не изменяются.
Сообщения подготовки идут в stderr; stdout используется только для MCP.
В используемом формате `.codex-plugin/plugin.json` относительный `cwd: "."`
задаёт корень установленного плагина. Аргумент `scripts/start-mcp.sh` разрешается
из этого каталога; подстановка переменных корня плагина в аргументы не требуется.

Сам запуск MCP не запускает веб-сервис. `get_service_status` только проверяет
состояние; `start_service` и операции с брифами/поисками запускают сервис при
необходимости. Ассистент возвращает пользователю его URL, обычно
<http://127.0.0.1:8765>. Несколько MCP-сессий используют один процесс и одну базу.
Файловые блокировки защищают от одновременного запуска двух владельцев данных.

Сервис работает отдельным процессом. Закрытие чата или MCP его не выключает.
Таймера простоя нет. Остановка — `stop_service` по просьбе пользователя или кнопка
«Остановить сервис» в браузере. Если идут поиски, нужно подтвердить их отмену.
Новые поиски во время выключения отклоняются. Полученные результаты сохраняются;
отменённые поиски получают статус `cancelled`. Очередь после запуска не возобновляется.

Остановленный MCP-инструментами сервис можно запустить следующим запросом.
Открытая страница показывает состояние остановки и кнопку проверки запуска.
Сама страница не запускает процесс. Удаление плагина также не заменяет остановку:
если сервис больше не нужен, сначала выключите его.

## Данные и обновления

| Назначение | macOS | Linux |
|---|---|---|
| База, состояние процесса, журнал | `~/Library/Application Support/Job Search` | `$XDG_DATA_HOME/job-search` или `~/.local/share/job-search` |
| Python, uv и окружения зависимостей | `~/Library/Caches/job-search` | `$XDG_CACHE_HOME/job-search` или `~/.cache/job-search` |

В каталоге данных находятся `search.sqlite`, `service.json`, файлы блокировок и
`service.log`. Сессия каталога хранится отдельно в `auth/session.json` с правами
только для владельца. Установленный плагин можно обновлять независимо от этих данных.
Новая сборка зависимостей получает отдельное окружение по хешу lock-файла.
Если уже работает другая версия сервиса, MCP предлагает остановить её и запустить
новую. При запуске версия схемы SQLite проверяется: поддерживаемые старые версии
обновляются автоматически в одной транзакции после создания проверенной копии
в `backups/`. Выпуск 0.4.0 использует Alembic: схемы 8 и 9 подключаются к его истории
после проверки структуры и старого журнала. Текущая ревизия — `0010`, она хранится
в `alembic_version`; собственный журнал миграций удаляется при переходе.
Неизвестная ревизия и неожиданные изменения структуры блокируют запуск.
При ошибке обновления изменения откатываются; копия остаётся для восстановления.

`service.log` ротируется по размеру: 10 МиБ на файл, пять архивных файлов.
Параметры — `JOB_SEARCH_LOG_MAX_BYTES` и `JOB_SEARCH_LOG_BACKUP_COUNT`.
Диагностика раннего запуска находится в `startup.log`, который заменяется при
следующем запуске. Автоматическое удаление резервных копий базы не выполняется.

Переменные окружения: `JOB_SEARCH_DATA_DIR`, `JOB_SEARCH_RUNTIME_DIR`,
`JOB_SEARCH_PORT` (по умолчанию 8765). Сервис слушает только `127.0.0.1`.
При занятом порте или неверном идентификаторе процесса чужой сервис не выключается.
Настройки источников и логирования допускают прежние `JOB_SEARCH_*` переопределения.

`start.command` и `python -m src` используют тот же менеджер процесса, каталог
данных и базу, что и плагин. Повторный запуск возвращает адрес существующего сервиса.
Для разработки задайте `JOB_SEARCH_DATA_DIR="$PWD/data/dev"` и `JOB_SEARCH_PORT=8766`.
База разработки создастся автоматически; обычная база останется общей для всех чатов.

## Слои кода

- `src/mcp/` — типизированные инструменты ассистента, перевод ошибок сервиса в MCP.
- `src/runtime/` — отдельный процесс, состояние, блокировки, запуск и остановка.
- `src/api/v1/service.py` и `src/services/lifecycle.py` — статус и остановка сервиса.
- `plugins/job-search/` — манифест, навык, обёртка запуска и готовый Python wheel.
- `.agents/plugins/marketplace.json` — каталог установки Codex.

MCP обращается к тому же HTTP API, что и браузер. Бизнес-логика и работа с SQLite
остаются в существующих сервисах. Есть 20 инструментов: управление сервисом,
источники, география, брифы, поиск, прогресс, результаты, события, этапы вакансий,
`authorize`, `get_company_filters` и `list_companies`. [Вход и каталог компаний](auth.md) используют
пользовательскую сессию Supabase.
Поиск контактов и карьерных лент работодателей не добавлен.

## Сборка и проверка

После изменения исходников нужно обновить пакет, включаемый в Git:

```sh
uv run python scripts/build_plugin.py
uv run python scripts/build_plugin.py --check
uv run pytest -q
uv run ruff check src scripts tests benchmarks
uv run mypy
node --check src/web/static/app.js
node --check src/web/static/auth.js
```

`build_plugin.py` проверяет версии, собирает wheel с SQL, интерфейсом, настройками
и географией, создаёт lock-файл с хешем wheel. В Git должны попасть все файлы
`plugins/job-search/runtime/`; окружения Python туда не записываются.

Проверка установленной копии через настоящий stdio MCP и HTTP:

```sh
uv run python scripts/plugin_smoke.py \
  --plugin "$HOME/.codex/plugins/cache/job-search/job-search/0.7.0" \
  --data-dir /tmp/job-search-check/data \
  --cache /tmp/job-search-check/cache \
  --output /tmp/job-search-check/report.json --cold --live
```

Каталог данных должен быть новым. `--cold` убирает Python и uv из PATH дочернего
процесса; для проверки полного скачивания используйте также новый каталог кэша.
`--live` выполняет небольшой поиск HH и Getmatch. Скрипт проверяет остановку,
повторный запуск, сохранность брифа/результатов и работу после отключения MCP.
В конце сервис выключается; `--keep-running` оставляет его для проверки браузера.

## Локальная география

Wheel включает `src/geography/data/cities.sqlite` и локализованные названия стран CLDR.
SQLite открывается только для чтения из установленного пакета. Справочник не копируется
в каталог данных, не распаковывается при запуске и не входит в резервную копию пользовательской базы.
Обновление справочника происходит вместе с плагином.

Перед `create_brief`/`update_brief` агент выбирает 1–5 городов через `find_cities` и передаёт
`country`, `geoname_id`, `city_display_name` (значение `name` из подсказки).
Старые брифы сохраняются, но для запуска требуют подтверждения городов. Версия `0.6.0`
отличает новый контракт от уже запущенного сервиса предыдущей версии.

Сценарии `benchmarks/scenarios.json` теперь содержат выбранную Москву. Измерения с ними
нельзя напрямую сравнивать с прежними запусками по всей стране или без географии.

В версии `0.7.0` формат и помощь с релокацией задаются внутри каждого элемента
`filters.locations`: `minimum_work_format`, `relocation_support`. Веб-форма объединяет
города одной страны с одинаковыми условиями в блок. Общий лимит — пять городов.
Исторические общие поля читаются; при сохранении значения переносятся в места.
