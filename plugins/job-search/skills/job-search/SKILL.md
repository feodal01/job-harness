# Поиск вакансий

Используй MCP-инструменты этого плагина. Сервис и зависимости поставляются вместе
с плагином: не проси клонировать репозиторий, запускать терминал или start.command.

## Вход и каталог компаний

Для входа вызови `authorize()` без параметров. Если `authenticated=false`, покажи
пользователю кликабельный `login_url`: он выберет доступный способ входа в браузере.
Не выбирай провайдера за пользователя и не опрашивай статус в цикле. После его
сообщения о завершении входа сразу вызывай `list_companies` с нужными фильтрами.
При `authenticated=true` дополнительный вход не нужен.

`list_companies` возвращает ссылки, способ их использования (`link_kind`,
`provider`), отрасли и специализацию. `name` и `specialization` ищут по части
текста; `category` — точное значение отрасли. Перед выбором категории вызови
`get_company_filters()` — он вернёт действующие значения и число ссылок для каждого.
Для текстовых подсказок вызови `get_company_filters(field="specialization", category=..., query=...)`.
`category` и `query` необязательны; используй их, чтобы сузить подсказки. Специализация
описывает продукт компании, а не профессию соискателя. Выбери подходящие ключевые
слова из подсказок для `list_companies(specialization=...)`; не копируй длинное описание целиком.
Фильтры объединяются через И. Поиск, группировка подсказок и пагинация выполняются
в Supabase; не выгружай весь каталог, чтобы фильтровать его самостоятельно.
Читай результаты постранично, обычно по 20
записей. При ошибке 401 покажи ссылку входа из ошибки. Это общий каталог для чтения;
его получение не запускает поиск вакансий на этих сайтах.

В веб-интерфейсе тот же вход открывается кнопкой «Войти». Сессия общая для
интерфейса и агента; обновляется автоматически. Не проси пользователя копировать
токены, ключи или пароль, не читай файл сессии и не передавай его содержимое в чат.
Обычный поиск HH/Getmatch и локальные брифы не требуют входа в каталог.

## Поиск по брифу

1. Уточни существенные условия брифа: профиль, географию, формат, зарплату и опыт.
   Сохрани исходный текст в `text`. Преобразуй условия в `queries` и `filters`
   по схеме `create_brief`. Не выдумывай неуказанные ограничения.
2. Через `list_sources` получи источники и их возможности. Это конфигурация и
   известное состояние, а не проверка доступности сайтов. Географию уточняй через
   `list_countries` и `find_cities`; дополнительного справочника HH нет.
   Подписи стран по умолчанию английские; `locale` можно передать явно, он не ограничивает
   язык поиска города. Для нового или обновляемого брифа обязательны 1–5 мест поиска.
   Из выбранной подсказки перенеси `country`, `geoname_id` и `name` как `city_display_name`
   в `filters.locations`. Сервер сам сохраняет ASCII-имя города и английское имя страны.
   У каждого места свои `minimum_work_format` и `relocation_support`; не задавай их
   общими полями `filters`. Места объединяются через ИЛИ; формат и помощь с релокацией
   проверяются вместе с географией того же варианта. В UI города одной страны с одинаковыми
   условиями показываются одним блоком; всего по всем блокам до 5 мест (город или вся страна).
   Не придумывай ID и не сохраняй введённую строку вместо выбора. Если результатов несколько,
   уточни город по региону. Если пользователь хочет всю страну, передай `scope="country"` и `country`,
   без `city`, `region`, `geoname_id`, `city_display_name`. Это одно место в общем лимите пяти.
   Пустой ввод города без явного выбора всей страны не разрешён.
   Старый бриф без ID читается, но перед изменением или запуском требует выбора городов.
3. Сначала проверь `list_briefs`, чтобы не дублировать существующий бриф. Создай
   или обнови нужный бриф. При обновлении передавай все его условия.
4. Запусти `start_search` с ID брифа, источниками и согласованными лимитами.
   Вызов возвращает ID запуска сразу. Проверяй `get_run` с разумным интервалом
   (например 3–5 секунд), не запускай повторный поиск вместо проверки состояния.
5. Читай `get_results` постранично или общую ленту `list_vacancies`. При ошибках
   проверяй `get_events`. Отличай завершённый, частичный и неудачный поиск.
6. Верни ссылку из `start_service` или `get_service_status`; для брифа добавь
   `/#/brief/<brief_id>/folder/open`. Результаты в браузере и MCP используют одну базу.

Обычные инструменты запускают сервис при необходимости. `get_service_status`
проверяет состояние без запуска. `stop_service` выключает сервис, сохранив данные;
MCP остаётся доступен. Вызывай его только по просьбе пользователя. Если есть
активные поиски, спроси о согласии на их отмену перед `cancel_active=true`.
Не останавливай сервис автоматически после завершения ответа. Таймера простоя нет.

Если сервис остановлен, новый запрос запускает его снова. Если порт занят,
состояние повреждено или версия сервиса отличается, передай понятную ошибку;
не удаляй базу, файлы состояния или чужие процессы для обхода ошибки.
После неопределённого результата записи сначала проверь сохранённые брифы/запуски,
не повторяй создание вслепую.

Ссылки на сайты работодателей могут быть в карточках. Не обещай поиск контактов
или поиск/парсинг карьерных лент: движок этого не делает. Изменение этапа вакансии
через `update_vacancy` не отправляет отклик работодателю.
